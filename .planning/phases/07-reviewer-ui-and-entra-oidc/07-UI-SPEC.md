# Phase 7 — UI Design Contract

> Visual and interaction contract for the reviewer UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope reminder: server-rendered Razor Pages in `Olive.Host`, plain semantic HTML, one local stylesheet, **zero JavaScript**. Accessibility, encoding and static copy matter more than visual polish (CONTEXT D-20, UI-06).

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none (not a React/Next/Vite project; shadcn gate not applicable) | CLAUDE.md stack, D-20 |
| Preset | not applicable | — |
| Component library | none. Razor Pages + Razor partials only | D-20, RESEARCH Standard Stack |
| Icon library | none. All affordances are text labels; no icon fonts, SVG sprites or images | default (CSP `default-src 'self'`, minimal UI) |

| Stylesheet | Exactly one file: `src/Olive.Host/wwwroot/olive.css`, served by `UseStaticFiles`, linked once from `Pages/Shared/_Layout.cshtml`. Target under 8 KB. CSS custom properties hold every token below | D-20, RESEARCH project structure |

## Spacing Scale

Declared values (multiples of 4), as CSS custom properties `--space-xs` … `--space-3xl`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a label and its inline hint; badge inner vertical padding |
| sm | 8px | Table cell vertical padding; gap between radio options; badge inner horizontal padding |
| md | 16px | Default gap between form controls; table cell horizontal padding; banner/flash padding; button horizontal padding |
| lg | 24px | Gap between page sections (`<section>`); header inner padding |
| xl | 32px | Space between page header and main content |
| 2xl | 48px | Top margin of the centered 403/404/signed-out panel |
| 3xl | 64px | Bottom page padding |

Layout:
- Content column: `max-width: 960px`, centered, horizontal page padding 16px (md).
- Definition lists (`<dl>`) for item fields: two-column grid, label column 200px, gap 8px (sm) vertical / 16px (md) horizontal; collapses to one column below 640px.

Exceptions:
- Buttons and the sign-out control: `min-height: 44px` (touch target), vertical padding 8px, horizontal padding 16px.
- Focus outline: 2px solid, offset 2px (not part of the scale; border widths are 1px or 2px).
- Rationale textarea: `min-height: 160px` (multiple of 4 but outside the scale).

## Typography

Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16px | 400 | 1.5 | Paragraphs, table cells, form inputs, textarea, flash and banner text, `<dd>` values |
| Label | 14px | 600 | 1.4 | Form labels, `<dt>`, table headers, badges, header bar text; monospace values (ids, refs, hashes) at 14px weight 400 |
| Heading | 20px | 600 | 1.25 | Section headings (`<h2>`): "Payload", "Claim", "Decision", "Hashes", "Execution chain", "History" |
| Display | 28px | 600 | 1.2 | One `<h1>` per page (page title) |

Rules:
- One `<h1>` per page; sections use `<h2>`; no `<h3>` and below.
- Hint/helper text uses Body size (16px, 400) in the muted text color; it is not a fifth size.
- Hashes and long refs use `overflow-wrap: anywhere` so 64-char hex never forces horizontal scroll.
- Timestamps render as `yyyy-MM-dd HH:mm 'UTC'` (invariant culture, UTC). Time remaining renders as `in 3 h 12 min` / `in 8 min` / `expired`, computed server-side at render time from the injected `TimeProvider`.

## Color

All pairs meet WCAG 2.2 AA (4.5:1 for text, 3:1 for UI boundaries). Tokens as CSS custom properties.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form inputs |
| Secondary (30%) | `#F3F4F6` | Header bar, table header row, `<dl>` panels, section panels; borders `#D1D5DB` |
| Text | `#111827` | All body text (16.8:1 on white) |
| Muted text | `#4B5563` | Hints, timestamps, secondary metadata (7.6:1 on white) |
| Accent (10%) | `#1D4ED8` | Reserved list below only (6.7:1 on white; white text on it 6.7:1) |
| Destructive | `#B91C1C` | Reserved list below only (6.5:1 on white) |
| Warning surface | background `#FEF3C7`, border `#B45309`, text `#78350F` | Fixture-trace banner, non-production environment banner |
| Success | text `#166534` on background `#DCFCE7`, border `#166534` | Success flash; "Recomputed proposal_hash matches" indicator |

Accent reserved for:
1. The single primary submit button on each page (Claim item, Submit decision, Sign in as … on the dev picker, Sign in again on the signed-out page): background accent, text white.
2. Text links (`<a>`), including the "Open" link in the queue table and "View audit history"; underlined always.
3. The keyboard focus outline on every focusable element (`:focus-visible`, 2px solid accent, offset 2px).

Secondary buttons (Release item, Sign out, Back to queue as button) use white background, `#111827` text, 1px `#4B5563` border. Never accent.

Destructive reserved for:
1. Error flash messages (border-left 4px destructive, text `#111827` on `#FEF2F2`).
2. The 403 page heading rule (4px top border on the panel).
3. "Recomputed proposal_hash does NOT match" indicator (text destructive on `#FEF2F2`, 1px destructive border).
4. Field-level validation message under the rationale textarea and the decision fieldset.

The Reject option is **not** colored destructive; Approve and Reject are equal-weight radio options (no visual nudge toward either outcome).

Color is never the only signal: every banner, flash and indicator starts with a text prefix ("Fixture trace", "Error:", "Done:", "Matches", "Does not match").

### Shared layout (`_Layout.cshtml`)
Top to bottom:
1. Skip link "Skip to main content" (visually hidden until focused), targets `<main id="main">`.
2. `<header>` bar (secondary background, 24px padding): left "Olive review queue" (Label size, links to `/review`); right, when signed in: "Signed in · {auth source label}" plus the reviewer oid in monospace, then a Sign out button (POST form with antiforgery). Auth source label: `entra` → "Microsoft Entra ID", `stub` → "Development fixture".
3. Non-production banner (only when `auth_source = stub`): warning surface, full width, text below.
4. `<main id="main">` with the page `<h1>`, then the flash region (if any), then page content.
5. No footer.

`<html lang="en">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`, `<title>` = "{page title} · Olive review queue".

### `/review` — Queue list (UI-02)
- `<h1>` "Review queue".
- Muted line: "Open items for tenant {tenant id, monospace}. Oldest first."
- `<table>` with `<caption>` "Open review items" (visually hidden) and `<th scope="col">`: Created · Age · Kind · Subtype · Subject · State · Expires · (link column header "Item").
  - Created: UTC timestamp. Age: from `AgeSeconds` ("2 h 05 min"). Expires: time remaining, or "No expiry" when `ExpiresAt` is null. State: badge text (`open`, `claimed`). Subject: `subject_ref` monospace. Item: link "Open" with `aria-label="Open item {item id}"`.
  - IR-1/list fields only (Phase 5 D-14). No payload values, no parameters, no justification on this page.
- Sort is fixed (oldest first). No sort controls, no pagination controls beyond the service default limit; if the service limit is reached, show muted line "Showing the oldest {n} items."
- Empty state (see Copywriting).

### `/review/items/{id}` — Item page (UI-03, UI-04, UI-05 banner)
Sections in order:
1. `<h1>` "Review item" + monospace item id beneath (muted).
2. Flash region.
3. Draft-restored notice (only on `?resume=` with a valid, single-use draft): success surface, `role="status"`.
4. Fixture-trace banner (only when `trace_verification = fixture`).
5. **Item** (`<h2>` "Item"): `<dl>` with Kind, Subtype, State, Subject ref, Payload ref, Claimed by (oid or "Not claimed"), Created, Expires (timestamp + time remaining).
6. **Payload** (`<h2>` "Payload"):
   - Holder of the kind's `required_role`: `<dl>` with Action type, On behalf of, Expires, Trace ref, Justification; then `<table>` "Parameters" with columns Name · Value (one row per top-level key, values as encoded text; nested objects/arrays shown as their compact JSON text, encoded, monospace).
   - Non-holder: notice text (see Copywriting); only the refs from section 5 are visible.
7. **Claim** (`<h2>` "Claim"):
   - `open`: primary button "Claim item".
   - `claimed` by current reviewer: text "You have claimed this item." + secondary button "Release item".
   - `claimed` by someone else: text "Claimed by another reviewer." No buttons.
   - `decided` / `withdrawn` / expired: text per state; no buttons.
8. **Decision** (`<h2>` "Decision") — rendered **only** when the current reviewer is the claimant and the item is `claimed` (D-11):
   - `<fieldset>` with `<legend>` "Decision", two radios: "Approve" (`value="approve"`) and "Reject" (`value="reject"`). Neither preselected, except when restoring a draft. `required`.
   - `<label for>` "Rationale" + `<textarea name="rationale" required maxlength="4000" aria-describedby="rationale-hint">`, `min-height: 160px`, full width.
   - Hint (`id="rationale-hint"`): see Copywriting.
   - Finality note above the button (muted).
   - Primary button "Submit decision".
   - Validation errors (server-side, after PRG) render above the fieldset as an error summary with `role="alert"` and next to the field; the textarea keeps the typed text only via the server-side draft store, never via TempData or query string.
   - For kinds whose registry `decisions` are not `[approve, reject]` (identity_review, configuration-only until Phase 8): the section shows the notice "Decisions for this item kind are not available in this release." and no form. [default]
9. Link "View audit history" → audit page. Link "Back to queue".

### `/review/items/{id}/audit` — Audit page (UI-05, D-13, D-14)
1. `<h1>` "Audit history" + monospace item id.
2. Fixture-trace banner (same rule as item page).
3. **Hashed fields** (`<h2>`): `<dl>` Action type · Party ref · Parameters (key/value table as on the item page) · Justification. Values visible only to holders of `required_role` (RESEARCH Q-C recommendation); others see the role notice instead of values.
4. **Hashes** (`<h2>`): `<dl>` `body_sha256` and `proposal_hash` (monospace, wrap anywhere), then the indicator: success surface "Matches: recomputed proposal_hash equals the stored value." or destructive surface "Does not match: recomputed proposal_hash differs from the stored value. Do not rely on this record." Shown to every tenant reviewer.
5. **Execution chain** (`<h2>`, decided action items only): `<dl>` Policy decision · Decision · Decided by · Rationale · Auth source · Decided at · Execution mode (`simulated`) · Started at · Finished at · Outcome · Reason. When no ledger row exists yet: "No execution recorded yet." When the item is not decided: section omitted.
6. **History** (`<h2>`): `<table>` caption "Queue item events", columns Seq · Event · From · To · Actor · At, ordered by seq ascending. `DetailJson` is not rendered.
7. Link "Back to item".

### Forbidden (403) page
Centered panel, max-width 640px, 48px top margin, 4px destructive top border, secondary background. `<h1>`, body paragraph, muted line "Reason code: {code}" (monospace, static code only), then actions. Copy per reason in Copywriting. For `role_not_held` the actions are: secondary "Release item" (POST to the item's release handler, antiforgery) and link "Back to item". For `no_reviewer_tenant` / `groups_overage`: Sign out button only (queue pages are all 403 for this session).

### Dev sign-in picker (`/dev/sign-in`, non-production only)
- `<h1>` "Development sign-in". Warning banner (non-production copy) at top.
- `<table>` caption "Fixture reviewers", columns Reviewer · Groups · Action. One POST form per row with a primary button "Sign in as {reviewer id}" (the only accent element; each row's button is the row's sole action).
- Honors a local `returnUrl` (validated with `Url.IsLocalUrl`; otherwise `/review`).

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Every POST | Antiforgery token (built-in Razor Pages validation, never disabled). Handler ends in `RedirectToPage` (PRG, 302/303). Never returns `Page()` from a POST. |
| Flash | TempData (cookie provider) stores **only a static code** (`claimed`, `released`, `decided_approve`, `decided_reject`, or a Phase 5 reason code). The page maps code → static copy. One-time read. Never contains rationale, parameters, exception text or claim values. |
| Flash markup | Success: `<div class="flash flash-success" role="status">`. Error: `<div class="flash flash-error" role="alert">`. Placed directly under `<h1>`. |
| Claim | POST → `QueueService.ClaimAsync` → PRG to item page with flash. |
| Release | POST → `QueueService.ReleaseAsync` → PRG to item page with flash. Available on the item page and the `role_not_held` 403 page. |
| Decide (fresh session or stub) | POST → freshness resolution (stub: fixture re-read, D-10; Entra: `auth_time` within window) → `QueueService.DecideAsync` → Phase 6 execution after commit → PRG to item page with `decided_*` flash. `role_not_permitted` result → 403 page `role_not_held`, item stays claimed (D-09). |
| Decide (stale Entra session, D-05) | POST → decision + rationale saved to the server-side single-use draft store (oid-bound, 10 min TTL) → OIDC challenge with `prompt=login` + `max_age=0` → IdP → callback → GET `/review/items/{id}?resume={opaqueKey}` → page shows draft-restored notice with radio and rationale prefilled → reviewer presses "Submit decision" again (normal POST). The resume GET never decides. The opaque key is the only thing in the URL. |
| Draft restore failure | Expired, used, or other-oid key: no restore, error flash `draft_unavailable`; form shown empty. |
| Re-auth evidence failure | `/auth/failed` with static copy; prior session not replaced. |
| Session expiry | 30 min idle sliding, 8 h absolute. Expired cookie on GET → redirect to sign-in with `returnUrl`. Expired cookie on POST → redirect to sign-in; the action is not performed and must be redone. |
| Sign-out | POST → clears reviewer cookie; Entra sessions also sign out at the IdP → `/signed-out`. |
| Keyboard | Logical DOM order equals visual order; all actions reachable by Tab; radios operable by arrow keys (native); no `tabindex` > 0. |
| Focus | `:focus-visible` outline 2px accent, offset 2px, on links, buttons, inputs, textarea, radios. Never `outline: none` without replacement. |
| Forms | Every control has a `<label for>`; required fields marked with the word "(required)" in the label, not color or asterisk alone. Server-side errors link to the field via `aria-describedby`. |
| Status codes | 403 page returns HTTP 403; 404 page returns HTTP 404; `/auth/failed` returns 400. |
| Caching | Pages under `/review`, `/dev`, `/auth` send `Cache-Control: no-store`. |

## Copywriting Contract

All copy is static. No user-supplied value (rationale, parameters, justification, exception text, token content) appears in flash, error or 403 copy. Values that appear in data sections are HTML-encoded by Razor.

### Primary elements

| Element | Copy |
|---------|------|
| Primary CTA (item page, open) | Claim item |
| Primary CTA (decision) | Submit decision |
| Secondary CTA | Release item |
| Decision radios | Approve / Reject |
| Rationale label | Rationale (required) |
| Rationale hint | Explain why you approve or reject. Do not paste record values, personal data or parameter values. Up to 4000 characters. |
| Finality note | Decisions are final. Approving runs the simulated executor immediately; no real system is changed. |
| Decision section, other kinds | Decisions for this item kind are not available in this release. |
| Payload hidden (no role) | You do not hold the role required to view this item's payload. You can see its references only. |
| Fixture-trace banner | Fixture trace: this proposal's trace was verified against a test fixture, not a live hometown answer. |
| Non-production banner | Development sign-in: you are using a fixture identity. This environment is not production. |
| Draft-restored notice | You signed in again. Your draft decision is restored below. Check it and select Submit decision to complete it. |
| Claimed by you | You have claimed this item. |
| Claimed by another | Claimed by another reviewer. |
| Decided state | This item has been decided. See the audit history for the record. |
| Withdrawn state | This item was withdrawn by its producer. |
| Expired state | This proposal has expired and can no longer be decided. |
| Execution not yet recorded | No execution recorded yet. |
| Hash match | Matches: recomputed proposal_hash equals the stored value. |
| Hash mismatch | Does not match: recomputed proposal_hash differs from the stored value. Do not rely on this record. |

### Empty state (queue list)

| Element | Copy |
|---------|------|
| Empty state heading | No open items |
| Empty state body | There is nothing to review in your tenant right now. New items appear here when they pass policy checks. Reload this page to check again. |

| Reason code | Heading | Body |
|-------------|---------|------|

|------|---------|---------------|

### Destructive / irreversible actions

| Action | Confirmation approach |
|--------|-----------------------|
| Approve / Reject (Submit decision) | Irreversible. No JS confirm dialog (no JS). Confirmation is structural: explicit radio choice with no default, required rationale, finality note directly above the button, and the decide-time re-authentication for stale Entra sessions. |

## Accessibility Contract

- WCAG 2.2 AA target. Contrast values in the Color table are the contract.
- Landmarks: `<header>`, `<main id="main">`; skip link first in the tab order.
- Tables: `<caption>`, `<th scope="col">`; definition lists for field/value pairs.
- Radios grouped by `<fieldset>`/`<legend>`.
- Errors: summary with `role="alert"` above the form; each field error referenced by `aria-describedby`.
- Text resizes to 200% without loss of content; no fixed heights on text containers except the textarea minimum.
- `prefers-reduced-motion`: no animations or transitions exist, so nothing to reduce.
