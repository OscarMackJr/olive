<objective>
Implement the tenant unit of work and the proposal store on top of the migrated schema, and prove both isolation layers with the layer-ablation tests.

Purpose: This is the persistence half of the Walking Skeleton and the pattern Phases 2-6 reuse. The database enforces RLS only if the app role is neither superuser nor owner and the tenant GUC is set per transaction, so the tests run as olive_app on a single pooled connection and remove each layer in turn.
Output: TenantUnitOfWork, ProposalSql, PostgresProposalStore, IProposalStore port, DB_05 and DB_06 tests.

Decisions applied: D-06 (state 'proposed' only, no awaiting_approval), D-07 (full v1 field set stored as received, nullable beyond run_id), D-08 (key_expires_at stored), D-10 (unique violation becomes a plain duplicate result), D-11 (cross-tenant lookup is indistinguishable from missing).

Scope note recorded as a decision: IProposalStore also exposes a compare-and-set TransitionAsync. D-06 forbids the skeleton from writing awaiting_approval and no endpoint calls it in Phase 1; it exists so DB-06 can prove the cross-tenant WRITE path through production SQL (the predicate-vs-RLS write ablation has no other production UPDATE to exercise). Phase 4 (POL-06) builds on it.
</objective>

    - `TenantUnitOfWork`: sealed class with primary constructor `(NpgsqlDataSource dataSource)` and `Task<T> ExecuteAsync<T>(Guid tenantId, Func<NpgsqlConnection, NpgsqlTransaction, Task<T>> work, CancellationToken ct)`. It rejects `Guid.Empty` with `ArgumentException`, opens the connection, begins an explicit transaction, executes the constant `select set_config('olive.tenant_id', @t, true)` with `@t = tenantId.ToString("D")` via Dapper on that transaction, runs `work`, commits, and lets disposal roll back on exceptions. It never uses session-level SET or SET LOCAL text. This file and MigrationRunner.cs (and a DatabaseSafetyChecks.cs added in 01-06) are the only src files allowed to open connections.
    - `ProposalSql`: static class of `const string` fields `Insert`, `InsertEvent`, `Get`, `UpdateState`, lowercase SQL. Insert lists all proposal columns with `@tenant_id` first, state literal 'proposed', `@parameters::jsonb`, ending `on conflict on constraint proposal_run_unique do nothing returning proposal_id`. InsertEvent inserts into proposal_event with `@tenant_id`, `@event_id`, `@proposal_id`, event_type/from_state/to_state/actor. Get selects all columns with `parameters::text as parameters_json` and the predicate `where tenant_id = @tenant_id and proposal_id = @proposal_id`. UpdateState is `update proposal set state = @to_state where tenant_id = @tenant_id and proposal_id = @proposal_id and state = @from_state`. Every constant contains `@tenant_id`; Get and UpdateState contain the literal `tenant_id = @tenant_id` (AGENTS.md: keep the predicate even though RLS exists).
    - `PostgresProposalStore`: sealed, implements IProposalStore, ctor takes `TenantUnitOfWork`. Set `Dapper.DefaultTypeMap.MatchNamesWithUnderscores = true` in a static constructor. Pass timestamps as `DateTime` via `.UtcDateTime` (Npgsql rejects non-UTC offsets), read timestamptz back as UTC and wrap in DateTimeOffset. Insert path: generate `Guid.NewGuid()` ids in code; if the insert returns no row return null WITHOUT inserting the event; else insert the `submitted` event in the same transaction. TransitionAsync updates then inserts a `transition` event only when one row was affected. No `try/catch` swallowing PostgresException.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host -> Persistence | tenant_id originates from the introspected key and is the only tenant source |
| olive_app -> Postgres | RLS applies only to a non-owner, non-bypass role with the GUC set |
| pooled connection reuse | A tenant setting must never survive past its transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-04-01 | Information disclosure | cross-tenant read | mitigate | App predicate (`tenant_id = @tenant_id`) plus forced RLS; DB_06 removes each layer in turn and shows the other blocks |
| T-1-04-02 | Tampering | cross-tenant write | mitigate | Same two layers; DB_06 asserts 42501 on cross-tenant INSERT and 0 rows on cross-tenant UPDATE/TransitionAsync |
| T-1-04-03 | Information disclosure | tenant GUC leaking across pooled connections | mitigate | `set_config(..., true)` inside an explicit transaction only; no session SET; tests with Max Pool Size=1 assert transaction-locality |
| T-1-04-04 | Elevation of privilege | unset tenant silently returns nothing | mitigate | Policies use current_setting without missing_ok; DB_06 asserts a PostgresException for unset tenant (fresh and reused) |
| T-1-04-05 | Tampering | SQL injection | mitigate | Parameters only (Dapper); the tenant GUC is set through a bind parameter; ablation helper validates table names against a strict regex |
| T-1-04-06 | Information disclosure | existence oracle via unique violation | mitigate | Uniqueness includes tenant_id; duplicate returns null; same (agent, run) in two tenants both succeed (tested) |
| T-1-04-07 | Information disclosure | Postgres error detail | mitigate | No Include Error Detail; store does not catch-and-rethrow messages; Host maps PostgresException to a generic problem in 01-05 |
</threat_model>
